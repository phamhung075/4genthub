SAFETY. Never git push, tag, deploy, change production configuration or touch production data without explicit approval from the human operator. A push to main auto-deploys to production at https://api.4genthub.com. Verify a deploy through the version reported by /health, and bump healthVersion in agenthub_go/fastmcp/server/httpapp/http.go with each release. Commit locally only when the lead asks. Never print secrets or tokens.

PROJECT. 4genthub is an agent orchestration platform. The backend is Go in agenthub_go, ported from the retired Python backend (recoverable from git tag python-backend-final). The frontend is React in agenthub-frontend. Storage is Postgres; authentication is Keycloak with JWT. OpenRig is the client and runtime; 4genthub is the cloud data for orchestration. The OpenRig integration lives under agenthub_go/fastmcp/seat_management (seats, rooms, modules, overlays, resolver) and the scripts/openrig_*.py client scripts.

LAYOUT.
- agenthub_go: Go server, packages under fastmcp/*, plan and backlog in NEXT_GEN.md and MIGRATION.md.
- agenthub-frontend: React app (src/pages, src/hooks, src/services, src/types, src/tests).
- scripts: operator and OpenRig client scripts.
- ai_docs: documentation.

TESTS.
- Go: run from agenthub_go with GOCACHE and TMPDIR set inside .gocache and .gotmp. Run go vet and go test ./... by package.
- Python scripts, from the repository root: python3 -m pytest --noconftest -p no:cacheprovider scripts/tests -q
- Frontend: npx vitest run, npx tsc --noEmit -p . (0 errors — the 23-error baseline was removed 2026-10-03), npx vite build.

WORKING RULES.
- Clean code only. No backward-compatibility code, fallbacks, legacy paths or migration helpers: this is a development phase with no production users.
- ORM and domain entities are the source of truth. When a test disagrees with them, fix the code to match the entity, then update the test.
- Make the smallest safe change and preserve unrelated behavior. Inspect the diff after editing.
- Add one new file `CHANGELOG/<date>--<title>.md` (root) for each project change (do not read the whole directory), agenthub-frontend/CHANGELOG.md for frontend-only changes, and TEST-CHANGELOG.md when test files change.
- Put tests only in the existing test locations. Create no new root files.
- Never read or create .env files; configuration comes from environment variables.
- Commit messages follow Conventional Commits, for example feat(seats): add room overlay.
- Report what you ran and its exact result; do not claim verification you did not perform.
