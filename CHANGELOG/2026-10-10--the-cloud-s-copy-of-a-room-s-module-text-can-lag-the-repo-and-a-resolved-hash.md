## The cloud's copy of a room's module text can lag the repo, and a resolved hash does not say so

### Added
- `ai_docs/operations/syncing-seats-with-the-cloud.md`: a "know before you use it" entry recording what a seat actually receives. `4genthub-min` serves a copy of the room module `project-4genthub` (version 1.0.0) that differs from its repo source `scripts/team/4genthub/project-4genthub.txt` in **three hunks** - the `PROJECT.` line still reads "being ported from the Python backend in `agenthub_main`" although the tree retired that backend; the LAYOUT bullet "`agenthub_main`: legacy Python backend; its script tests live in `agenthub_main/src/tests/scripts`." still exists although the repo deleted it; and TESTS still carries that pre-move pytest command **plus a TypeScript-error baseline the tree removed on 2026-10-03**. The guide block is stale the same way (`guide-reviewer` still names the pre-move pytest command), as is the commit-discipline text, which still tells seats to `git add -- <path>` and stage first where the settled form at `shared-modules/guide-common.md:22` is a pathspec commit with **no** pre-stage. The same resolved snapshot hash came back on 2026-10-08 21:23Z and on 2026-10-10, which rules out a stale cache but **not** a publish that landed unreferenced, because an unreferenced version changes nothing a seat sees; `GET /api/v2/openrig/modules` (latest per module, with `sha256`) or `GET /api/v2/openrig/modules/{slug}/versions/{version}` (404 when absent) is the one command that separates the two. A corrected body must also go out as a **new** version and the refs must name it - `modulecontent.go:4` makes a module version immutable and the manifests name literal versions - so an unreferenced publish renders the old row and looks exactly like a publish that never happened.

### Verified
- **Served versus repo, by diff, not by reasoning about hashes.** `call_seat('4genthub-min','reviewer')` was written out and its `## project-4genthub` section diffed against the repo source: **three hunks**, as above. Its `## Guide: reviewer (quality gate)` section diffed against `seedlibrary/blocks/guide-reviewer.md`: **exactly one line** (the pytest command), while the *same served block* already carries the corrected statement that the baseline was removed - so the cloud holds a copy from between 2026-10-06 and 2026-10-08. The served commit-form line reads `Stage explicit paths only: git add -- <path> then git commit …` against `guide-common.md:22`'s `Commit by pathspec and do not stage first`.
- **The stale text is in the cloud, not in the tree.** Every repo authoring source is clean; the corrections are committed (`0ea06c77` 2026-10-08 the path move, `1f0b177a` 2026-10-06 the baseline, `d1114170` 2026-10-09 the `agenthub_main` retirement). Six authoring sites still *name a count* while doing so (`scripts/team/4genthub/mission.md:7`, `area-web-frontend.txt:11`, `project-4genthub.txt:14`, `area-quality.txt:9`, `blocks/guide-fe-dev.md:13`, `blocks/guide-reviewer.md:16`) - a separate question from freshness, and one the owner's no-count rule now settles: the count is to be deleted.
- **The count itself is dead.** At tip `f0d30b65`, in a clean detached worktree with `node_modules` symlinked in (the shared tree held 45 dirty entries), `npx tsc --noEmit -p .` exited **0** with **zero** `error TS` lines and empty stdout.
- **Read-only on the cloud side:** nothing was published, no seat was restarted, no seat was reconfigured; publishing is the principal's token, and a seat cannot read the live module versions.
