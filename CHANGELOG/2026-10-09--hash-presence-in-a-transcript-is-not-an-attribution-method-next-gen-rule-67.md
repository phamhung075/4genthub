## Hash presence in a transcript is not an attribution method — NEXT_GEN rule 67, from the trial arm's own re-derivation

### Added
- `agenthub_go/NEXT_GEN.md`: **rule 67 — HASH PRESENCE IN A TRANSCRIPT IS NOT AN ATTRIBUTION METHOD, AND NEITHER IS HASH PRESENCE IN THE OUTPUT OF YOUR OWN COMMAND.** The two failing forms are measured, not argued. (i) A test for "does my session store contain this commit hash" marked **ALL 74 of the day's commits as the writer's** — fe-dev's, go-dev's and the architect's among them — because **every seat's hash passes through a transcript every time anyone reads `git log` or a handoff file.** (ii) The tightened form — "does the hash appear in the output of my own `git commit` call" — **fails identically**, and the instance is recorded: **`105dadba` (`fix(team_setup)`, another seat's commit) was confirmed as the writer's that way**, because the same shell call that commits also prints a `git log` tail and a neighbouring commit's hash sits in that tail. **A hash in an output tells you the commit EXISTS NEAR YOUR WORK, never that you made it.**
- **The three instruments that do work, each with its blind spot stated:** **(i) the `Seat:` trailer** (added by `prepare-commit-msg`) — decisive where it exists, **BUT ITS POPULATION IS PARTIAL AND IT HAS NO CLEAN ONSET, WHICH A CENSUS SETTLED AGAINST THIS ENTRY'S OWN FIRST DRAFT — AND ITS "EARLIEST" IS WINDOW-DEPENDENT, WHICH IS THE PART THIS BULLET FIRST GOT WRONG: MEASURED OVER THE COMMITS SINCE `2026-10-08T00:00:00+02:00` — THE WINDOW STATED AS A FULL TIMESTAMP WITH ITS TIMEZONE, BECAUSE A WINDOW QUOTED AS A BARE DATE IS NOT MERELY A DIFFERENT WINDOW BUT A MOVING ONE, WHICH IS RULE 68'S INSTANCE WITH ITS NUMBERS — GIT FILLS THE MISSING TIME-OF-DAY FROM THE CLOCK — so at 22:30:39 local it and `--since='2026-10-08 22:30:39'` read the SAME count in one invocation (97 at `50dde4b7`), while `--since=2026-10-08T00:00:00+02:00` reads 175 (the same contrast at `95df9793` was 93 against 171); THE SAME DATE STRING PRODUCES TWO WINDOWS, SO A WINDOW IS REPRODUCIBLE ONLY WHEN THE DATE CARRIES ITS PARSE. THE CENSUS COUNT OF 164 IS ATTRIBUTED TO THIS FILE'S `390e6e1a` ENTRY RATHER THAN ASSERTED HERE (see that entry), READING BOTH `%(trailers:key=Seat)` AND THE RAW BODY, the earliest commit carrying a `Seat:` line is `44c81bcb`, 2026-10-08 18:33:49Z — A DAY EARLIER than the 19:00:03Z this entry first claimed — BUT OVER THE WHOLE HISTORY THE EARLIEST IS `ca6574e8`, 2026-10-06T18:35:32+02:00, TWO DAYS BEFORE IT, whose trailer reads `4genthub-min.web-dev` (`3e4b2605`, `c81eff94` and `7ba67f9e` follow it the same evening), SO AN UNWINDOWED "EARLIEST" IS FALSE AND THE WINDOW MUST TRAVEL WITH THE CLAIM. WITHIN THAT WINDOW `cd472751` IS NOT THE FIRST (its own DIRECT PARENT `5a2fc602`, and `4814b711` a minute before it, both already carry one), and within that same hour some commits carry the line while others carry none (`12006c50`, `9ba5a358`). SO ABSENCE OF A TRAILER IS NOT EVIDENCE ABOUT WHO AUTHORED A COMMIT: read it as "no trailer", NEVER as "not this seat", and any attribution that treats the trailer as switched on at a time will silently undercount the seat's own work**; **(ii) the per-commit gate file** in the seat workspace, which names the author in its prose (`GATE-a2ff4332-row8-2026-10-09.md` reads "matches the architect's report") or in its filename; **(iii) the commit confirmation in the authoring seat's own store** — valid only as the git commit line for that call, never as any hash appearing anywhere in its output, and it misses every commit whose output was truncated.
- **The tie-break, which is the part that keeps a list honest: A LIST BUILT BY AGREEMENT BETWEEN TWO COUNTS IS NOT DERIVED — agreement proves only that the counts SHARE A BLIND SPOT.** State the instrument behind every attribution, and the window it covers.
