## FindProjectRoot no longer resolves by directory NAME, so a seat's build caches stop deciding the project root

### Fixed
- `agenthub_go/fastmcp/task_management/infrastructure/utilities/directory_utils.go`: **loop 2 is deleted, not gated** (`30dfd7e9`). It returned the parent of any directory literally named `agenthub_go` *without consulting `Env.Exists`*, so the parity test's stub — which guards `Exists` and not names — could not stop it. With the build caches in their mandated home (`agenthub_go/.gotmp/…`), the upward walk ran out of the fixture, met the REAL `agenthub_go`, and answered `/home/daihu/__projects__/4genthub` to a case expecting `<R>/data`. **Red on the real tree, measured both ways:** `TMPDIR=/tmp/…` ok, `TMPDIR=agenthub_go/.gotmp/…` FAIL at `directory_utils_test.go` case 2. Deleting is not tidying: gated on `Exists` the loop would be **unreachable**, because a hit at `cur` means `Exists(parentOf(cur)/agenthub_go)` already held and loop 1 returned there.
- The `has()` **probe** keeps its renamed marker and is not part of this change, because it consults `Env.Exists` and the fixture stub therefore controls it. Deleting loop 2 alone is sufficient **with the probe rename in place** — that is the state this was measured in.
- The two dead repeats inside the data-path fallback went with it: `has(e.Cwd)` is decided earlier in the same call, and the walk-up loop is loop 1 again. Every return left satisfies one of three shapes — a directory that holds `agenthub_go`, the data path when it exists, or `/tmp/agenthub_project` — so the fallback is now provable rather than incidental.

### Verified
- `directory_utils_test.go`: `TestFindProjectRootParity` (**120 cases exercised**, logged) and the new `TestFindProjectRootIsHostIndependent` both PASS under `TMPDIR=/tmp/…` AND `TMPDIR=agenthub_go/.gotmp/…` — **10 tests in the package, exit 0 both ways**. The new case is **RED on the parent commit under `TMPDIR=/tmp`** (`returned ".../001", the parent of the fixture's own agenthub_go: the search matched a NAME`), which is what makes it a case rather than a restatement of the fix.
- `go test -count=1 ./...` exit **0** — **144 packages ok, 0 failures**; `gofmt -l` on both files prints nothing.
