## Rule 2 consults real ownership, not an environment string

### Fixed
- `agenthub_go/fastmcp/server/routes/websocket_routes.go` — **`routes.Ownership` was declared and never assigned**, so `CheckResourceOwnership` (Rule 2 of `IsUserAuthorizedForMessage`) always fell through to its environment answer: it returns true only when `ENVIRONMENT` is exactly `development`, case-insensitively, defaulting to `production` — so **production refused every system-triggered cross-user frame while development delivered it to every connection**, and in neither case was ownership ever asked. The Python reference has no seam here: `_check_resource_ownership` queries `Task`/`Subtask`/`ProjectGitBranch`/`Project` directly, filtered by `user_id` (read from git history, because `a50929c6` retired the Python backend from the tree). The environment fallback is faithful porting and **stays**: it is the answer when the check cannot be made at all.
- `agenthub_go/fastmcp/server/httpapp/ownership_wiring.go` (new) — `ownershipChecker` implements the interface with those four queries, and `NewApp` assigns it. Modeled on `wireMissedNotificationStore` next door, the same defect class: an injected global that no production code assigned. It **counts** rows instead of selecting one, so `COUNT` always answers and a real failure is never confused with "no such row"; a genuine error is returned as an error, which Rule 2 treats as "cannot tell" and answers from the environment exactly as before.
- Four claims the wiring falsifies are corrected in the same commit rather than left behind: the `Ownership` doc comment said nil "behaves as not-found" (it falls through to the environment), and `task_application_facade.go` plus `task_update_broadcast_test.go` (its header and its failure message) said Rule 2 has no implementation to consult.

### Verified
