## The client feature plan's status lines now name what ships, and the README table is the binary's own output

### The finding, and the premise checked rather than copied

The lead's docs-accuracy row (`qitem-20261011204722-c3b36fdf436ec40e`) came from go-dev's own finding while
landing item 5 of `ai_docs/operations/client-features-for-the-dev-team.md`, and both halves were re-measured
rather than relayed.

**The client README's command table listed 24 verbs; the shipped binary prints 31.** The table's own
introduction claims to be "the list the binary itself prints", so the verbs the table omitted were invisible
to a reader who trusted it: `doctor`, `overlap`, `rigd`, `guard`, `send`, `evidence` and `worktree`. Seven
descriptions had also drifted (`up` still described the stack without `rigd`, `compact` was still
"(re)start the compaction supervisor ... detached", `stop` still named the bridge rather than rigd's
children, `status` still named only the supervisor's process, `offpeak` predated the seat-start gate).

**The plan document still presented all six items of its section 4.7 as work to do, and all six ship.** Read
off the binary and the client's history: `4genteam doctor` (item 1), `guard` (2), `send` (3), `overlap` (4),
`stuck` (5), and the item-close done report printed by `evidence` (6). Eight `Missing`/`Partly` lines in
section 1 were wrong for exactly those items, including the seat doctor line that said "the worktree and
skill checks are not built" while `4genteam doctor 4genthub-min` prints F1 cwd/worktree, F2 foreign-skill and
F3 missing-skill rows.

### The change

**The client half** (`agenthub_client`, branch `4genthub-min/go-dev`, its own CHANGELOG entry): the README's
command table is now `4genteam --help` verbatim - all 31 verbs, in the binary's order, each description the
binary's own words - and the four rows that carried operator detail a one-line table should not hold
(`offpeak`'s exit codes, `continue --all`, `watchdog`'s flags, `stuck`'s ten-minute cadence) moved into a short
list under the table so the rows stay checkable against the binary.

**This half**: section 1's eight status lines corrected in place, each naming the commit that landed the item
(the first touch of that item's own file); a second-pass note at the head so a reader knows which pass the
words are from; and a new section 4.8 whose table names all six items, where each lands, and its landing
commit - `9182f13` (doctor), `96a09a1` (guard), `90845c2` (send), `57d92bf` (overlap), `4fa2c7c` (stuck),
`a98e78b` (done report).

### Verified

- The README table equals the binary, MECHANICALLY rather than by reading: a script that runs
  `go run ./cmd/4genteam --help` in the client worktree, parses the verbs and descriptions it prints, and
  compares them with the README's rows reports **31 verbs, order equal, verb sets equal, 0 description
  mismatches**.
- `4genteam doctor 4genthub-min` was run (read-only, exit 3 because rows are not running) before the
  seat-doctor line was rewritten, so that line describes rows that were observed rather than rows read out of
  a package.
- The six landing commits are each the first touch of the file named beside them (`git log --diff-filter=A`),
  and `a98e78b` was confirmed twice: by `-S printDoneReport` and by the live `4genteam evidence --help`, which
  prints the done report's own description.
- No Go test, guard or generator reads this document or the client README; nothing else had to move with it.

### Not changed, named

- `ai_docs/index.json` was left alone. It is generated by `.claude/hooks/utils/docs_indexer.py`, it was
  generated 2026-10-10, it lists 20 files, and it is already missing this document and two other
  `operations/` files. Regenerating it inside this change would land every other seat's uncommitted `ai_docs`
  file in this commit - the churn this repository already has a CHANGELOG entry about - and the row does not
  ask for it.
- Section 1's lines for the items that are still open (branch and merge status board, dependency check,
  standup digest, handoff note, audit log, forbidden-actions list, per-seat cost, review queue limit,
  load balancing, pre-merge automation) were left as they were, because the binary does not contradict them.
- `CHANGELOG/2026-10-11--session-start-cleanup-narrow-matcher.md` sits untracked in the shared checkout and is
  not this seat's file; it was left for its owner.
