## The session carries the seat it belongs to, and a stale generated-model marker stops lying

### Added
- **`agent_sessions.room_slug` and `agent_sessions.seat_key`** — the seat identity a connector already holds, reported at ingest and stored beside the session it names. Null means the connector could not name a seat, which is a fact about the session rather than an error. The pair is carried together: `CONSTRAINT ck_agent_sessions_seat_pair CHECK ((room_slug IS NULL) = (seat_key IS NULL))` states that to the database, so no path can store half of it.
- **`fastmcp/session_stream/session_columns.go`** — the column ensurer for a database that ALREADY holds the table, because `createAll` creates a table only when it is absent; without it the pair would exist everywhere except the schema that matters. Idempotent by construction (`ADD COLUMN IF NOT EXISTS`, constraint dropped then re-added), registered into `ColumnEnsurers` by `init`, and reached only under `AUTO_MIGRATE=true` — the same shape `seat_management`'s ensurer documents.

### Changed
- **`session_stream.UpsertSession` takes the pair and validates it before any statement is built** (`seatIdentity`): both or neither, and each half must match the repository's own name rule — imported from `seat_management/domain/repositories` rather than copied, so there is one statement of it. That import is a pure domain package: no query and no foreign key, so the hot socket path still does not depend on `seat_management`'s storage. On an update the pair moves only when the frame carried one, so a client that cannot name a seat never erases the answer an earlier frame gave — the rule `project` already follows.
- The session DTO carries `room_slug` and `seat_key` beside the existing keys (`sessionRow`, `sessionCols`, `scanAgentSession`). The HTTP list route needs no change: it is written from the ordered map.
- **`ws_mount.go`'s session frame reads `room` and `seat`** and hands them to the writer; a refused pair answers with the writer's own message rather than "internal error", which is why `wsAppendError` is now described as mapping both stream writers instead of only `append_events`.
- **A STALE GENERATED-MODEL MARKER IS CORRECTED, in the same commit as the edit it blocked.** `models.go` opened with "Code generated from infrastructure/database/models.py (SQLAlchemy metadata); DO NOT EDIT" — and no `models.py` and no generator script exist anywhere in this repository, nor in `agenthub_main` (checked by `find` and by `git grep`). A do-not-edit marker whose generator is gone is the same defect class as a citation that rots: text asserting a cause it cannot read, and this one had already stopped an editor from making an ordinary change. The header now records the origin, that the generator was REMOVED WITH THE PYTHON TREE, that the file is HAND-MAINTAINED, and the date and reason of the correction.
