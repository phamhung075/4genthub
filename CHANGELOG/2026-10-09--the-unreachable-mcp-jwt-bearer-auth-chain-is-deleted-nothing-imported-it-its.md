## The unreachable MCP JWT/bearer auth chain is deleted: nothing imported it, its own adapter could not match it, and the live validator is a different package

### Removed
- **`agenthub_go/fastmcp/server/auth/` — five ported files and their three test files (`auth.go`, `mcp_auth_config.go`, `providers/{bearer,in_memory,jwt_bearer}.go`, `auth_test.go`, `mcp_auth_config_test.go`, `providers/jwt_bearer_test.go`) — and `server.TokenVerifierAdapter` with its three interfaces (`tokenVerifier`, `accessTokenLoader`, `userTokenExtractor`) in `fastmcp/server/http_server.go`** (row `ecea11ab`, ruled by the lead after `f49014a3`). Deleted as UNREACHABLE rather than repaired, and **the shape of the evidence is what makes the size safe**, not the size:
  - **Nothing outside the package imports it.** `grep -rn '"agenthub/fastmcp/server/auth"'` over `agenthub_go` returns only files INSIDE it, and the same holds for `.../auth/providers`.
  - **`MCP_AUTH_TYPE` had THREE hits repo-wide:** the read at `mcp_auth_config.go:45` inside the deleted `GetDefaultAuthProvider`, its test's `t.Setenv`, and one `PROD_READINESS_REPORT.md:110` sentence.
  - **The chain's ROOT had no caller.** `ConfigureMCPServerAuth` was called by nothing at all, so `GetDefaultAuthProvider` → `CreateMCPAuthProvider` → `NewJWTBearerAuthProvider` hung off a function nobody called; that is why the provider and both middleware-bridging pieces were removed rather than kept with a test.
  - **`NewJWTBackendFunc` was declared, read at `jwt_bearer.go:73-74`, and assigned nowhere**, so the provider it fed answered `(nil, nil)` — no token and no error.
- **THE ADAPTER COULD NOT HAVE WORKED ANYWAY, kept because it is the strongest single fact:** it asserts a one-result `VerifyToken`, then a one-result `LoadAccessToken`, then a string `ExtractUserFromToken`, while `JWTBearerAuthProvider` returns `(*AccessToken, error)` and has **no** `ExtractUserFromToken` — it matched none of the three branches and fell through to `return nil`. `NewTokenVerifierAdapter` was constructed only in `http_server_test.go`.
- **THE LIVE PATH IS UNTOUCHED AND NAMED: `fastmcp/auth.ValidateTokenUniversal` (`unified_token_validator.go:33`), used at `mcp_routes.go:158` and `:358` and `ws_mount.go:116`** — a different package, so a next reader asking where an MCP request authenticates must not look in `fastmcp/server/auth`. The `AUTH_ENABLED` readers are also untouched and still live (`dual_mode_config.go:136`, `mcp_routes.go:167`, `httpapp/http.go:189`, `ws_mount.go:263`); they decide whether auth is ON, not which validator runs.
- **A STRING-KEYED ROUTE WAS CHECKED TOO, because a package can be reached by a NAME in a config rather than by an import:** the removed type and symbol names were swept as strings across the non-Go file types (`yaml`, `yml`, `json`, `sql`, `sh`, `py`, `ts`, `tsx`, `toml`, `conf`, `ini`, `env`, `md`) over the whole repository. **Every hit is in `scratch/` (gitignored, `.gitignore:381`) or `logs/` (gitignored, `.gitignore:109`)** — working notes and offload transcripts, not config, not code: **zero tracked non-Go files name any removed symbol.**
- **Bookkeeping in the same commit, because a second source of truth about the tree is what we do not keep:** `MIGRATION.md` rows 529-533 now read `removed-unreachable` with the reason per row, and `NEXT_GEN.md` records it under *Environment facts useful to the next session* as an unreachable deletion that names the live validator.
- **One comment named a deleted symbol and is corrected rather than left standing:** `fastmcp/server/httpapp/facade_wiring.go:73` said the JWT-secret refusal was "the SAME decision `providers.NewJWTBearerAuthProvider` and the REST dependency chain make". The REST chain makes that decision; the deleted provider no longer exists to agree with anything.
- **FINDING THIS ROW DID NOT ACT ON, reported instead:** `fastmcp/server` now has **no importer either** — `MCPHeaderValidationMiddleware` is referenced by its own test only — so `http_server.go` is a candidate for its own row. It stands because this cutover's ruling named the adapter block.
