## The context-pack algebra threw a context phase's provenance away; the label now travels with the atom

### Changed
- `agenthub_go/fastmcp/seat_management/domain/contextpacks/compose.go`: `resolvePieces` takes `[]labelled` — an atom paired with the source label it was SELECTED under — instead of a bare atom slice plus one `sourceKindFor func(Atom) SourceKind`. A per-atom function cannot label the same atom twice, and a context phase may carry several sources, so the label had to move onto the selected atom rather than stay in a function the phase could not inform. `ComposeNamedProfile` now labels AT SELECTION from the phase being walked: **a context phase's pieces carry the name they were supplied under** (its `contextAtoms` key), while an atom phase carries no source name of its own and is therefore library by construction. `ComposeProfile` keeps its behaviour exactly: the caller's per-atom producer labels the walk, and library is the default when none is supplied.
- `agenthub_go/fastmcp/seat_management/domain/contextpacks/types.go`: **`SourceSlice` added**. `ProfilePhase`'s own comment and the locked vocabulary name project/mission/seat/**slice** as the context sources while `SourceKind` had only library/project/seat/mission, so a slice source had no truthful label to resolve to. `sourceKindsByName` is now the ONE place a context source's kind is resolved; an unknown name is refused loudly rather than silently labelled library.
- **The one deliberate divergence from the OpenRig port it ports.** `profile-composer.ts:244` hands one caller-supplied `sourceKindFor` to every phase, so a context phase's atoms lose the source they were supplied from — the defect the B2 ruling corrects (lead, concurred by the architect against the code): whoever supplies the bytes labels them, resolved from the phase being walked, never a store lookup inside the algebra and never derived from the address, because a ref is untyped and the caller's resolver owns what it names (`address.go:46-50`).

### Verified on the tree, not on the prose
- The acceptance test fails before the change and passes after it: `cd agenthub_go && go test -count=1 -run TestComposeNamedProfileLabelsContextSourcesFromThePhase ./fastmcp/seat_management/domain/contextpacks/` -> before, `labels = ["library" "library"], want [project mission] — a context phase takes the name it was supplied under` (the same atom supplied under two sources collapsed onto one label); after, `ok agenthub/fastmcp/seat_management/domain/contextpacks 0.002s`.
- Whole package after: `go test -count=1 ./fastmcp/seat_management/domain/contextpacks/` -> `ok agenthub/fastmcp/seat_management/domain/contextpacks 0.003s`; `gofmt -l` on the package prints nothing; `go vet ./fastmcp/seat_management/domain/contextpacks/` -> rc 0; `go build ./...` -> clean.
