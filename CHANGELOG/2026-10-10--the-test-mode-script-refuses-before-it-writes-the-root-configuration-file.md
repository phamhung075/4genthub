## The test-mode script refuses before it writes the root `.env`, instead of printing success for a switch it never made

### Fixed
- **`scripts/run-mcp-tests.sh`** — the script performs TWO writes in the repository root: `.env` is copied to `.env.backup` (a single slot, not a history — every run replaces it), then `.env.testing` is copied over `.env`. `.env.testing` is gitignored and absent unless somebody creates it, so the protection was a file nobody can see in `git status`, and at HEAD that state read as success: the second copy failed, there was no `set -e` to stop the run, and the script printed `✅ Switched to testing configuration`, restarted the stack and announced `🚀 TESTING MODE READY` for a switch that never happened — with `.env.backup` ALREADY REPLACED by whatever `.env` held at that moment. The fix:
  - A **precondition before the first write** (`if [ ! -f .env.testing ]` → a loud three-line refusal naming what is missing and stating that `.env` and `.env.backup` are untouched, `exit 1`). It sits before the backup copy deliberately: a refusal placed at the failing copy would still have overwritten the single backup slot first.
  - **`set -e`**, so a later failure stops the run instead of being stepped over — which is what makes each success line conditional on the step it describes.
  - The health check is written as `if curl …; then` rather than `curl …` followed by `if [ $? -eq 0 ]`, because under `set -e` a failing curl would end the script before the branch that reports it.
  - The restore hint now says the backup is one slot rather than a history.

### Testing
- **Failing first**, and the failure is the defect verbatim. New test file `scripts/tests/test_run_mcp_tests_env_guard.py` (run with `--noconftest -p no:cacheprovider`, 2 cases). Against the script at HEAD, in a scratch directory, with `docker-compose`, `curl` and `sleep` stubbed on `PATH` so no real container can be reached: `test_a_missing_testing_env_fails_loudly_and_writes_nothing` **FAILED** on `assert result.returncode != 0` — the run returned **0**, stderr carried `cp: cannot stat '.env.testing': No such file or directory`, and stdout carried `✅ Switched to testing configuration` and `🚀 TESTING MODE READY`.
- **The backup's identity, measured separately at HEAD** because the test stops at its first assertion: in a scratch tree with `.env` and `.env.backup` holding different bytes, the HEAD script left `.env`'s mtime untouched but replaced `.env.backup` **both in bytes (`4dd38d67…` → `aef651bc…`) and in mtime**. In the real tree today the two files hold identical bytes, so the loss is the mtime only — which is exactly why the test asserts digest AND mtime rather than content.
- **After the fix:** `2 passed in 0.02s`. The second case is the guard's other side — with `.env.testing` present, `.env` holds the testing configuration, `.env.backup` holds the configuration that was replaced, and the container step is reached, so the precondition refuses a doomed run without refusing a good one.
- **Bounds observed:** the tests never read, create, print or commit a root `.env` member and never run the script against the real tree — every `.env` member they use is synthetic and written by the test itself into `tmp_path`, and the stub `PATH` makes the container steps inert.
- `scripts/run-mcp-tests.sh` is **tracked at HEAD** (last touched by `6a57e00e`), so this is a change to a live script rather than an untracked leftover.
