## Both recorded digests of a mirrored skill are read, not just the source's: 2 of the 54 sides carried a digest nothing verified

### Fixed
- **`agenthub_client/src/agenthub_client/team_setup.py:709` — the per-side read is one function now, `_verified_skill_text(name, path, recorded, source_root, side)`, applied twice.** The inlined read it replaces verified the canonical copy and stopped: a mirrored skill's `mirror_sha256` was recorded, published into the block, and **never compared against the mirror's file**, so 2 of the 54 row-sides — `messaging-the-human` and `openrig-skills`, the two rows carrying both edges — could rot green. Both sides refuse with the same `SetupError`/`EXIT_USAGE`, and `side` (`source`/`mirror`) is in the sentence, so a reader learns which half of the pair moved.
- **`skill_library_modules()` (`:734`) reads the mirror at `:764-768`, and only when the row has one** — `mirror is not None` still guards the append, so the 50 single-edge rows are untouched and the published block's `mirror_path`/`mirror_sha256` are what they were. The mirror's TEXT is deliberately not added to the block: the inventory records the same skill on both edges, so the read is verification, not content.
- **The message gained one word, said here because the failure text is what the test reads:** the refusal now reads `skill 'x': source /path/SKILL.md digests …`, where it read `skill 'x': /path/SKILL.md digests …`. No test pinned the old text — checked across `*_test.py`, `*_test.go` and the client's own fixtures for both the sentence's tail and the bare `skill '` prefix — so the label is an addition, not a re-pin.
- **The module docstring claimed more than the code did, so it changed with the code:** `:49-51` said "the file read is verified against the inventory's digest"; it now says "the file reads are verified against the inventory's digests — the source's and its mirror's".

### Added
- **`agenthub_client/tests/test_team_setup.py`: `test_the_inventory_curation_accounts_for_every_skill`, with `_curation_gaps(inventory)` as the rule** — the four ways a hand-maintained inventory can fail to account for its own 52, each as a sentence: a curated name that is no row, an `unused_by_default` name that is no row, a row that is neither, a skill that is both. It needed a home because **the row artefact `F1-DIGEST-RERUN-2026-10-09.py` retires in this change** — the condition the previous entry pre-registered ("it retires when the mirror is verified in the shipped path") is now met — and that script was the only check of these four.
- **Why the Go side does not already cover it, rather than assumed:** `TestLoadEmbeddedSeedsCarryCuratedSkillRefs` (`seedlibrary_test.go:398`) checks that every curated ref resolves and reaches its seed, and that every `unused_by_default` name reaches no seed. **A misspelled unused name passes that check by reaching no seed either**, and nothing anywhere asserted the arithmetic that the 52 are accounted for exactly once. Both are the hole this closes.
- **Hermetic, and it says so:** no checkout is involved, so it is the one guard here that does not skip on a machine that has never cloned OpenRig.
