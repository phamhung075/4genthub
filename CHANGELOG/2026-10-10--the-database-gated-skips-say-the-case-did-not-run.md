## The database-gated skips say the case did not run, and how to run it

### Changed
- **Fifteen files under `agenthub_go/fastmcp/` — 17 sites — now print a LOUD skip when their database URL is unset:** `SKIPPED, NOT PASSED: <VAR> is unset, so this case did NOT run - <the command that supplies the credential>`. Before, each said only `<VAR> not set`, which reads as coverage for a case that never ran. This is the same defect one level down from `newMissedNotificationAppEnv` (fixed in `1a81ddc5`), and the class rule 24 in `agenthub_go/NEXT_GEN.md` already writes it down: a skip is a result to report, not an absence to omit.
- What each text names, so a reader can act without opening the file: **`AGENTHUB_TEST_PG_URL`** (9 sites, 8 files) → `bash tools/testpg/start.sh` prints a URL to pass to it. **`SEAT_TEST_DATABASE_URL`** (7 sites, 6 files) → it applies the seat schema to a PostgreSQL it is given, and the same script prints one. **`TEST_DATABASE_URL`** (1 site) → it needs a DSN whose database **already carries the production-like schema**, which the note at the top of `models_prod_test.go` describes; the text says that rather than pointing at the cluster script, because the script alone does NOT satisfy that case.
- **Scope: the skip TEXT only.** No CI change, no new coverage, no gate moved. The skips that state a real environment fact rather than a coverage gap — `/bin/sh` on Windows, running as root, `rig` not on PATH, and the `OPENRIG_TEST_AGENT_VALIDATE` opt-in that already names its own command — were left exactly as they were.
