## The `manage_agent` tool, the `agents` table and the 32-role registry are retired

### Removed
- The tool surface: `fastmcp/server/httpapp/mcp_routes.go`, `fastmcp/task_management/interface/{ddd_compliant_mcp_tools.go,ddd_compliant_mcp_tools_wiring.go,tool_input_schemas.go,facade_provider.go}`, `interface/mcp_controllers/agent_mcp_controller/**` (11 files: controller, description, crud/assignment/rebalance handlers, formatter bridge, factories), `interface/adapters/simple_multi_agent_adapter{,_test}.go`, `interface/api_controllers/agent_api_controller.go`, and the `manage_agent` entries in `infrastructure/configuration/tool_config.go`, `interface/utils/json_parameter_parser.go` and the golden `interface/testdata/tools_golden.json`.
- The agent library behind it: `application/use_cases/{register,assign,get,list,unregister,unassign}_agent.go`, `application/use_cases/rebalance_agents_use_case.go`, `application/services/agent_coordination_service{,_test}.go`, `application/services/work_distribution_service{,_test}.go`, `application/event_handlers/agent_event_handlers.go`, the six `application/dtos/agent/**` files plus `dtos/common/agent_role.go`, `domain/repositories/agent_repository.go`, `infrastructure/repositories/agent_repository{,_factory,_factory_test,_test}.go` and `repositories/cached/cached_agent_repository.go`, `infrastructure/services/agent_converter{,_test}.go`, and the agent workflow-guidance library (`interface/mcp_controllers/workflow_guidance/agent/**`, 3 files).
- The facade family: `application/facades/agent_application_facade.go`, `application/factories/agent_facade_factory.go`, `facade_service.go`'s `agentFacadeFactory` interface, struct field, constructor parameter and `GetAgentFacade`, plus the `facade_wiring.go` / `app.go` wiring that built them.
- The registries: `domain/value_objects/agents.go` and `domain/value_objects/agent_roles.go` (the 32-role table), and the role branch inside `normalizeAssignee` in `domain/entities/task.go` and `domain/entities/subtask.go`.
- The schema: the `agents` CREATE in `infrastructure/database/init_schema_postgresql.sql` and its TableDef in `infrastructure/database/models.go`. The unrelated `agents` JSON **column** on seats (`seat_tables.go:257`) is untouched, because it is a different thing that happens to share a name.
- The auth surface: the developer source's `"agent": ["manage_agent"]` key in `fastmcp/auth/mcp_keycloak_auth.go`.

### Changed
- **`@<seat_key>` is now the only assignee identity.** A bare name - a seat key like `go-dev` or a retired role like `coding-agent` - is refused with `Invalid assignees: [...]. An assignee is '@<seat_key>'.`, and the wording that promised "or a known agent role" is gone from the task and subtask controller messages.
- The committed API reference the docs page renders, `agenthub-frontend/src/docs/apiReference.ts`, was **regenerated by its producer** (`go run ./cmd/apirefgen` from `agenthub_go`): 145 routes, 9 tools, and the diff is exactly the `manage_agent` entry (61 lines) - no route moved.
- The frontend and the client still name `manage_agent` in places this change deliberately did not touch: `apiReference.ts` is regenerated here, but the frontend page copy and client policy are steps 5-6 of the plan and stay with their seats.

### Found, and deliberately left alone
- `fastmcp/auth/config/token_costs.go` still prices retired agent operations (`register_agent`, `get_agent`, `list_agents`, `update_agent`, `unregister_agent`, `assign_agent`, `unassign_agent`, `rebalance_agents`, `assign_agent_branch`, `unassign_agent_branch`). It is a port of `agenthub_main`'s `token_costs.py`, the plan's enumeration does not name it, and no live tool reads those rows; deleting them is a separate decision rather than a silent one here.
- **The `manage_task` tool DESCRIPTION still promises the retired rule**, at `fastmcp/task_management/interface/mcp_controllers/task_mcp_controller/manage_task_description.go`'s `assignees` parameter: "a known agent role such as 'coding-agent' is accepted and becomes '@coding-agent'. A bare name that is not a known role is rejected." That sentence is now false and it is user-visible - an agent reading the description is told a value the tool rejects. It was not changed here because `TestToolDefinitionsMatchPythonToolRegistry` pins the Go description to `interface/testdata/tools_golden.json`, a snapshot of the **Python** server's registry, so fixing it is a coordinated Go + Python + golden change that the plan's step 2 does not name.
- The live git-branch `assign_agent` action still illustrates itself with the retired identities: `interface/mcp_controllers/workflow_guidance/git_branch/git_branch_workflow_guidance.go` carries `agent_id="coding-agent"`, `assignees="coding-agent"` and "Assign coding-agent, test-orchestrator-agent, or other specialists", mirrored in the golden. This plan does not retire that surface (the action, its handler and its description test are live), and its wording is a product decision rather than a by-product of the deletion.
