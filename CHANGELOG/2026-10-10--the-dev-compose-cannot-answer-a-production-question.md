### Fixed
- **What the claim said, by file and line.** The addendum (`2026-10-10--a0-measured-against-the-pin-…md:8`) reads: "the `AUTO_MIGRATE` condition is now verified rather than inferred … (`docker-system/docker/docker-compose.backend-go-frontend.yml:36` sets `AUTO_MIGRATE: ${AUTO_MIGRATE:-true}`; `ai_docs/verification/schema-upgrade-gate.md:22` records that production boots an EXISTING database with it true)." The cited line is real. **The line above it is the problem**: `:35` reads "Local dev database only: the Go server runs DDL only when this is true (default off)". The compose is the local dev lane and its own comment states the opposite of its substitution, so it cannot describe what production runs. Read as a pair, `:35-36` are not evidence of anything about the deployed server.
- **Why no repository file could answer it, measured in full (read-only, 20:13Z).** `captain-definition.backend`, `captain-definition.backend.go`, `docker-system/docker/captain-definition` and `docker-system/captain-definition-mcp-fix` carry only `schemaVersion`, `dockerfilePath` and — in two of them — an nginx snippet: **no `AUTO_MIGRATE` anywhere**. The Dockerfile all four point at, `docker-system/docker/Dockerfile.backend.go`, sets none either. The only `AUTO_MIGRATE` occurrences anywhere under `docker-system/` are that dev-compose line and `docker-system/lib/configuration.sh:184`, which merely validates that the value is `true`/`false`. The production value therefore lives in the deployment platform's application environment, where the repository cannot show it.
- **What the evidence actually is: the database, not a file.** The live `task_events` gained `user_seq` and `client_event_id` between the 18:19Z write error naming `user_seq` and the 19:43Z error naming `subtask_id` — and the only code that adds those two is `EnsureTaskEventColumns` (`agenthub_go/fastmcp/task_management/infrastructure/database/task_event_ensurer.go`), which runs **only** when `CreateTables` runs under `AUTO_MIGRATE=true` at boot. An independent second half, already recorded: `agenthub_go/NEXT_GEN.md:369` carries `go-dev`'s `docker inspect` of the live container `srv-captain--4genthub-backend.1.jrg5g7b2r24gig91np4knrwxk` on 2026-10-05, reading `AUTO_MIGRATE` as exactly `true`.
- **The conclusion survives; only the citation was wrong.** Production boots with `AUTO_MIGRATE=true`, and the deploy path is not in question: a build containing `a0313d5f` should repair the board with **no environment change**, because the same ensurer that added the other two columns adds `subtask_id`. The owner's single statement — `ALTER TABLE task_events ADD COLUMN IF NOT EXISTS subtask_id UUID` — remains the zero-dependency option, since the column is nullable with no data move and no `NOT NULL` step.
