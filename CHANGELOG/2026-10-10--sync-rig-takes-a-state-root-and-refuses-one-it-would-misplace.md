## `4genteam sync rig` takes `--state-root`, and refuses a seat that reads another one

### Fixed
- `agenthub_client/src/agenthub_client/seat_sync.py`: the render of every seat - its `.mcp.json`, its `config.yml`, its `AGENTS.md` - was written under the module's own state root and could not be told otherwise, so a seat launched with `rig launch --state-root <other>` got its files placed under the DEFAULT root, where its omp never reads them, and nothing said so. `rig` now carries the same `--state-root` flag `seat-policy apply` already carries, with the same machine-level default (`seat_policy.DEFAULT_STATE_ROOT`, which is where the module constant now comes from, so the value has one home), and the chosen root is threaded to every site that read that constant: `omp_agent_dir`, the resolve pass, and the per-seat policy pass. The default is byte-identical, so nothing an operator runs today changes.
- When a seat is RUNNING under a different root than the chosen one, the run refuses before writing anything, naming both roots and the flag. `launch_state_root` reads the runner's own argv, which is where a launch states its root: every seat's runner is started as `pi-runner.js --session-name <session> --state-root <root> --cwd <room> --launch-id <id>`. A seat that is not running answers None rather than a guess, so a rig whose seats have never been up still gets the agent directory it adopts at its first launch, and there is no silent fallback to the default anywhere.
- **The refusal that was REMOVED is stated here rather than left to be inferred**, which is what the reviewer asked of the earlier entry: an overridden `--state-root` used to be refused with a message naming the flag, and that refusal was deleted when the client was made to create the agent directory for a rig that has never been up. What replaces it is the flag above, plus the mismatch refusal. The two comments that still promised the deleted refusal (the caller's, and the `omp_render_installs` docstring) now describe what the code does.
