## The census runs where the suite runs, and its third instrument is tracked

### Added
- `scripts/S3-REDERIVE.py` — the seat-local re-derivation of §3's table anchors (`ai_docs/api-integration/surface-inventory.md` §3.1–§3.4, the Declaration and SQL columns), now in the tree with ROOT derived from its own location instead of one seat's checkout. Reading discipline unchanged: `git show` only, never the worktree, so it measures a commit; anchor species `def` (the ORM TableDef entry), `reg` (the registry attach line) and `sql` (the DDL line). New `--self-test` (perturb one anchor in a COPY by +7; require the delta AND the name) and `--doc-file PATH` (audit a copy). No write mode at all: read-only by design.
- `scripts/tests/test_census_audits.py` (9 cases) — the wiring: the canonical suite now runs `scripts/CITATION-AUDIT.py`, `scripts/COUNTS-AUDIT.py` and `scripts/S3-REDERIVE.py` as SUBPROCESSES rather than imports (which is how a gate runs them, and an import cannot catch a bad `__main__`), each one's `--self-test`, S3-REDERIVE's missing-base branch, and CITATION-AUDIT's `--write` refusal with the inventory's sha256 checked before and after. Every clean run must also state how much it READ, so an instrument that silently audits nothing cannot read as clean.

### Changed
- **The verdict of `scripts/S3-REDERIVE.py` is stronger than the seat-local copy's, and that is the substantive change.** The copy returned 0 unless an anchor was `STALE->BATCH` or `UNRESOLVED`, so an anchor stale since BEFORE the attribution base (`STALE->EARLIER`) PASSED — a check that cannot fail, the shape this fleet refuses everywhere else, and porting it unchanged would have wired that shape into the suite. The tracked version exits non-zero on ANY not-fresh anchor; `BATCH` versus `EARLIER` still prints, as attribution rather than absolution. Red by effect: with ONE §3 anchor shifted +7 in a copy, the run exits 1 and names inventory line 470 (`agent_sessions`) as `STALE->EARLIER` — precisely the case the old verdict waved through.
- The attribution base may be ABSENT, and a shallow CI checkout is the normal case. The base is attribution, not the verdict, so the run prints `BASE UNAVAILABLE: <rev> is not in this checkout, so drift could not be attributed ... git fetch --deepen=200 origin ...` and still prints its FRESH/STALE verdict; a rev absent from the checkout at all is REFUSED (exit 2), and an unknown argument is exit 2. Never a silent pass.
- `ai_docs/api-integration/surface-inventory.md`: §3.5's pointer and §1's census paragraph now name `scripts/S3-REDERIVE.py` beside the other two instruments, with what it reads and what makes it fail.
