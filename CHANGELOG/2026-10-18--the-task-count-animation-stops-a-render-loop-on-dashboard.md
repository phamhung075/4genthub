# The task-count animation stops driving a render loop on /dashboard

`/dashboard` logged React's `Maximum update depth exceeded` because `useProjectAnimations` kept its previous counts in state and wrote that state on every effect run, with `previousTaskCounts` itself in the dependency list. While the branch-summaries query has no data, `useBranchSummaries` hands out `data?.branches ?? []` - a new empty array per render - so `ProjectList`'s `taskCounts` memo was a new object per render, each effect run committed state, and the consumer re-rendered forever. The previous counts now live in a ref (memory, never rendered), the effect depends on `taskCounts` alone, and it writes state only when a count actually changed; the animation's 600 ms timer is cleared on unmount. New test `agenthub-frontend/src/tests/components/ProjectList/useProjectAnimations.test.tsx` (3 cases): the equal-but-new input settles (red on the old hook: 21 renders, green now: 1), a change animates up and clears, and a decrease reports `down`. The existing `ProjectList.test.tsx` mocks this hook, which is why the loop shipped.
